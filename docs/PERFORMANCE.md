# 性能基线

> 对应版本：7.2.0（§1–§5 空闲基线）、7.3.1（§6 启动时间）。**注意：这是「当前机器上的运行实例」实测，不是隔离干净环境的复测**。仓库中没有更早的性能基线数据可复测（`docs/history/winforms-notes-v1-v3.9.md` 只有定性经验，没有数字）。

## 1. 本次实测（2026-11-06）

测试对象：正在运行的 `WindowTinter.exe`（7.2.0，单文件框架依赖发布，799,510 字节）。

测试方法：`Get-Process` 读取 `TotalProcessorTime`，间隔 10 秒前后各采样一次；内存取 `WorkingSet64` / `PrivateMemorySize64`；`Threads.Count`。

| 指标 | 数值 | 说明 |
|---|---|---|
| CPU（单核百分比） | **0.16%** | 10 秒窗口内 CPU 时间增量 ÷ 10s ÷ 1 核 |
| CPU（整机百分比） | **0.01%** | 28 个逻辑处理器 |
| 进程累计 CPU 时间 | 1.62 s | 自本次启动以来 |
| 工作集（Working Set） | **134.2 MB** | WPF 应用常驻 |
| 私有内存（Private） | **109.1 MB** | |
| 线程数 | 26 | |
| 句柄数 | 1,302 | `Process.HandleCount` |

## 2. 测试条件（必须连同数字一起引用）

- 操作系统：Microsoft Windows 11 IoT 企业版 LTSC
- 逻辑处理器：28
- 显示缩放：96 DPI（100%）
- 目标列表：**空**（`Targets: []`，没有任何被压暗窗口，底板未创建）
- 主窗口处于正常使用状态；桌面有其它应用程序在运行（**非干净环境**）
- 采样窗口：10 秒，单次采样；未做多次取均值
- 版本：7.2.0（`FileVersion 7.2.0.0`）

**结论**：空闲（无目标）时 CPU 占用可忽略（<0.2% 单核）；内存约 134 MB 工作集，属于 WPF + .NET 6 的常态水平。

## 3. 未测量的场景（不要引用上面的数字去推断）

- 绑定 1 个 / 3 个 / 10 个目标时的 CPU 与内存
- 拖动滑块、频繁刷新快照、目标窗口快速移动时的峰值 CPU
- 最小化/还原、切换虚拟桌面（cloak）时的瞬时开销
- 24 小时以上驻留的内存增长（是否有泄漏）
- 快照线程（`PrintWindow`）的单次耗时
- WinEvent 回调频率（桌面级 `LOCATIONCHANGE` 被句柄过滤前的事件量）

## 4. 已知的性能相关设计（代码事实）

- WinEvent 回调线程先按**已绑定句柄**过滤（`_boundHandles` 数组），不把全桌面事件投递到 UI 线程。
- `ApplyEntryEffect` 用 `LastAlpha` 差异计算，alpha 不变不调系统 API。
- 底板位置在 500ms 轮询 + WinEvent 驱动下更新，不是逐帧跟随。
- 快照改为手动/首次抓取，不再 3 秒定时抓图；同一目标已有 `PrintWindow` 在跑时不重复排队。
- 设置保存有 200ms 防抖（滑块拖动）。
- 跨进程 `SetWindowPos(SWP_FRAMECHANGED)` 会阻塞调用线程，代码里用 `RedrawWindow` 异步替代（见 `AGENTS.md`）。

## 5. 复测方法（供后续补充数据）

```powershell
$p = Get-Process WindowTinter
$c0 = $p.TotalProcessorTime.TotalMilliseconds
Start-Sleep -Seconds 10
$p.Refresh()
$c1 = $p.TotalProcessorTime.TotalMilliseconds
"单核 CPU% = " + [math]::Round(($c1-$c0)/1000/10*100,2)
"工作集 MB = " + [math]::Round($p.WorkingSet64/1MB,1)
```

复测时请记录：OS 版本、逻辑处理器数、显示缩放、绑定的目标数量与类型、是否有其它负载、采样时长。只有条件一致的数字才能对比。

## 6. 启动时间实测（2026-11-15，v7.3.1）

测试对象：`WindowTinter.exe` 7.3.1，单文件框架依赖发布，796,830 字节；每次启动前均为**热文件缓存**（连续重复启动），且保证没有其它实例占用单实例 Mutex。

测试方法：C# 计时器在 `Process.Start` 前启动，每 3–5ms 轮询 `EnumWindows`：
- 托盘就绪 = 进程出现 `WPFTaskbarIcon_*` 窗口类（`TaskbarIcon` 已创建）
- 主窗口可见 = 进程出现可见的 `HwndWrapper[WindowTinter*` 顶层窗口
- 压暗生效 = 进程出现可见的 `WindowTinter.BlackPlate` 底板窗口（需目标窗口存在）
- UI 输入空闲 = `Process.WaitForInputIdle(5000)` 返回

| 场景 | 指标 | 中位数 | 范围 | 样本 |
|---|---|---|---|---|
| 静默启动 `/startup`，无目标 | 托盘就绪 | **306 ms** | 290–312 ms | 10 |
| 静默启动 `/startup`，1 个目标（记事本） | 压暗生效（底板可见） | **320 ms** | 317–340 ms | 3 |
| 静默启动 `/startup`，1 个目标（记事本） | 托盘就绪 | **351 ms** | 348–372 ms | 3 |
| 正常启动，显示主窗口 | 主窗口可见 | **392 ms** | 389–404 ms | 5 |
| 正常启动，显示主窗口 | UI 输入空闲 | **418 ms** | 416–433 ms | 5 |
| 对照：7.2.0 正常启动 | 主窗口可见 | 403 ms | 391–405 ms | 5 |
| 新拷贝首次运行（近似冷启动） | 主窗口可见 | 439 ms | 单次 | 1 |

启动时资源（静默 / 正常）：

| 指标 | 静默启动 | 正常启动（窗口可见） |
|---|---|---|
| 启动累计 CPU 时间 | 312 ms（中位数） | 484 ms（中位数） |
| 工作集 | 72 MB | 126 MB |

> CPU 时间大于墙钟时间是因为 JIT / GC / 渲染线程并行，属于正常现象。

**测试条件**：

- Windows 11 IoT 企业版 LTSC 24H2（26100），Intel i7-14700F（20C/28T），64 GB 内存，96 DPI（100%）
- 文件缓存已热（非重启后的首次运行）；桌面有其它应用程序在运行（**非干净环境**）
- 计时包含 .NET 主机启动，不含用户双击/资源管理器启动的点击延迟

**结论**：静默启动约 0.3 s 托盘就绪、1 个目标时约 0.32 s 压暗生效；正常启动约 0.39 s 窗口可见、0.42 s UI 空闲。单文件发布与多文件构建（热缓存约 392 ms）没有可测差异。7.3.1 与 7.2.0 的启动差异在噪声范围内。

**未测量 / 不要据此推断**：

- 严格冷启动（需要清空系统文件缓存 / standby list，本机未安装相应工具，未执行）
- 开机登录瞬间与其它自启项、杀毒软件扫描并发时的启动耗时
- 机械硬盘、USB 便携盘、网络盘上的启动耗时
- 125% / 150% / 200% 高 DPI、混合 DPI 多屏下的首帧渲染时间
- 首帧真正呈现时间（只测到 `IsWindowVisible` 与 `WaitForInputIdle`，不是 DWM 上屏时间）
